# 🚀 CPU-Scheduler-Comparison

본 프로젝트는 운영체제(OS) 설계 과제의 일환으로 진행되었으며, **멀티레벨 피드백 큐(MLFQ)** 기반의 스케줄링 알고리즘 두 가지를 설계 및 구현하여 성능을 비교 분석했습니다.

## 📌 프로젝트 개요
* **목적**: 다양한 프로세스 환경에서 스케줄링 알고리즘의 효율성 비교 분석
* **핵심 지표**: **정규화된 반환시간 (Normalized Turnaround Time, NTAT)**
* **개발 환경**: C++, AI 도구(ChatGPT, Claude) 활용

---

## 🛠 구현 알고리즘 소개

### 1. DRS (Dynamic Response Scheduler) 
시스템의 반응성과 공정성을 동시에 확보하기 위해 **SRTF**와 **HRRN**을 결합한 하이브리드 모델입니다.

* **Q1 (SRTF)**: 남은 실행 시간이 가장 짧은 프로세스를 우선 처리하여 응답성을 극대화합니다.
* **Q2 (HRRN)**: 대기 시간을 고려한 응답률(Response Ratio) 기반 스케줄링으로 긴 작업의 기아(Starvation) 현상을 방지합니다.
* **강등 로직**: Q1에서 40단위 시간 이상 실행된 프로세스는 우선순위가 낮은 Q2로 이동시켜 CPU 독점을 방지합니다.

### 2. MLFQ-PR Scheduler 
전통적인 MLFQ 구조에 우선순위 기반 제어를 강화한 모델입니다.

* **구조**: Real-Time Queue(RTQ) + 3개의 우선순위 큐(Q1~Q3) + FIFO 큐(Q4)
* **특징**: 설정된 시간(Time Quantum) 내 미종료 시 우선순위를 낮추어 하위 큐로 재배치하는 공정한 자원 분배를 지향합니다.

---

## 📊 성능 비교 결과 (Average NTAT)
세 가지 시나리오를 통해 분석한 결과, **DRS** 알고리즘이 짧은 작업 및 혼합 환경에서 우수한 효율을 보였습니다.

| 시나리오 | 특성 (Computing Time 기준) | MLFQ-PR (NTAT) | DRS (NTAT) | 우수 알고리즘 |
| :--- | :--- | :---: | :---: | :---: |
| **Scenario A** | 짧은 프로세스 위주 ($< 40$) | 5.89 | **2.857** | **DRS** |
| **Scenario B** | 긴 프로세스 위주 ($\ge 40$) | **5.89** | 7.315 | **MLFQ-PR** |
| **Scenario C** | 혼합형 작업 (Short & Long) | 4.99 | **2.818** | **DRS** |

> **분석 결론**: 일반적인 시스템 환경(혼합형)에서는 DRS 알고리즘이 더 적합하며, 긴 작업 비중이 높은 환경에서는 MLFQ-PR이 안정적인 성능을 보입니다.

## 🤖 AI 도구 활용 및 디버깅 성과
단순히 AI가 생성한 코드를 사용하는 것에 그치지 않고, 직접 로직을 검증하며 완성도를 높였습니다.

1. **로직 교정**: AI가 누락한 시간 경과(Type 1) 처리 로직을 직접 구현하여 시뮬레이션의 정확도를 확보했습니다.
2. **HRRN 기준 수정**: 큐 진입 시점이 아닌 프로세스 도착 시점부터의 대기 시간을 계산하도록 로직을 변경하여 신뢰성을 높였습니다.
3. **교차 검증**: ChatGPT가 생성한 결과물을 Claude를 통해 검증하고, 수동 계산값과 대조하여 최종 코드를 도출했습니다.
